## Rendering and provenance

Blender 4.3.2 official CPU renderer and FFmpeg 7.1.5 available. Official Blender archive checksum verified. The Debian Blender build lacked OpenImageDenoise, so the official build was installed. A denoised still was rendered for inspection; CPU denoising was slow. The complete motion study uses Cycles at 540×960, 16 samples, 30 fps, film transparency. **No 1080p master has been rendered.**

Scene audit measures 605 objects and 87,720 mesh polygons, no external image files, perspective camera and changing head/mid-body distances, limb rotations and jaw rotation across frames. Geometry includes raised scales, ventral plates, branched horns, teeth, claws, whiskers, mane locks and dust. These measurements prove scene structure/articulation, not premium aesthetics or physical realism.

All scene geometry/materials/motion are generated by the supplied original script. No third-party model or texture was incorporated. A potential CC Attribution model by MAXDESIGN-3D was researched; Sketchfab's download endpoint returned HTTP 401 without authentication, so no model was obtained or redistributed. Existing MP4 licenses were not newly verified by this work.

## Playback findings

Inspected the actual `flutter_vap_player` 2.1.1 and `vap_player_android` 2.1.1 packages, not just call sites. Native dependency is Tencent VAP 2.0.28. `VapPlayerController.asset`, `VapPlayerOptions`, `VapPlayer`, completion/error event classes and explicit initialization/disposal are present. Native renderer reads alpha/RGB rectangles and requests an 8-bit alpha EGL surface. Existing room rocket code invokes this API, but is not evidence of a verified device run.

The candidate packs full-resolution alpha and straight RGB into H.264 with a real appended `vapc` v2 metadata box. At 540×960 display, encoded size is 1088×960; alpha rectangle `[0,0,540,960]`, RGB rectangle `[544,0,540,960]`. It must use a VAP compositor, never plain `video_player`. Independent review caught the fixed H.264 level being insufficient for a future 1080 export; regression coverage now selects 4.1 or 5.1 from actual packed macroblock limits.

The FFV1 BGRA master is for lossless review/archive, not Android playback. CPU verification compares every decoded master frame exactly with the PNG sequence and checks decoded VAP mask/color. Independent review prompted a regression proving that a frame-count-correct opaque FFV1 master is rejected.
